How to play

Xiangqi is played on the points where lines cross, not inside squares — a board of 9 files by 10 ranks, split across the middle by the river. Each side has a 3×3 palace marked with a diagonal cross. Red moves first. Click one of your pieces to see where it can go (a dot, or a ring on a capture), then click the destination.

帥 將General (K)One point orthogonally, and never leaves the palace. The two generals may never face each other on an open file — the flying general rule — so a move that would leave them facing is illegal.
仕 士Advisor (A)One point diagonally, inside the palace only.
相 象Elephant (E)Exactly two points diagonally, and can't cross the river. Blocked if the point it jumps over (the "elephant's eye") is occupied.
傌 馬Horse (H)One point orthogonally then one diagonally outward, like a chess knight — but it's hobbled: blocked if the point directly next to it in that direction is occupied.
俥 車Chariot (R)Any distance orthogonally, like a chess rook. The strongest piece.
炮 砲Cannon (C)Moves like a chariot, but captures only by jumping over exactly one piece (of either colour), the screen, onto the enemy piece behind it.
兵 卒Soldier (P)One point forward. Once across the river it may also step sideways. It never moves backward and never promotes.

You win by checkmating the enemy general — and, unlike chess, also by stalemating it: a side with no legal move loses. Perpetual check is forbidden: if the same position comes up a third time and one side has been giving check on every move of that cycle, that side loses; any other threefold repetition is scored a draw. (Tournament rules also forbid perpetual chasing of an unprotected piece; that finer rule isn't adjudicated here, though the engine knows it.)

To play the computer, set Play against to Computer — Fairy-Stockfish, pick a side and a strength, and play. Level 1 makes plenty of mistakes; level 8 is the engine at full strength. In this mode Undo takes back your last move and the computer's reply. The move list uses WXF notation: piece letter, the file it starts on (numbered 1–9 from each player's own right), then + advance, - retreat or = sideways, then the number of points moved (for pieces moving straight along a file) or the destination file. So C2=5 is "cannon on file 2 moves across to file 5" — the classic Central Cannon opening. When two identical pieces share a file, +/- replace the file number for the front/rear one.

How the code is built

The game is this one HTML file — no build step, no libraries — plus the optional engine, loaded on demand. All the JavaScript lives in one function (an IIFE) at the bottom, split into labelled sections with // === banners, following the Chess sub-app:

  • The rules (BOARD LOGIC) — pure functions over a 10×9 array of single-letter piece codes, the same letters Fairy-Stockfish uses in its FEN (K A B N R C P for Red, lowercase for Black; B is the elephant and N the horse). No DOM, no shared state.
  • Notation (moveToWXF) — turns a move into WXF notation, working in each side's own file numbering and its own idea of "forward".
  • The engine (ENGINE) — loads Fairy-Stockfish and talks UCI to it.
  • The screen & the glue (RENDER, ANIMATION, FLOW) — the only code allowed to touch the DOM.

Every piece is one small rule in pseudoMovesFor

A move is just [fromRow, fromCol, toRow, toCol] — Xiangqi has no castling, en passant or promotion, so no flags are needed. The horse checks its "leg" point before jumping, the elephant checks its "eye" and its own side of the river, and the cannon walks outward in each direction: empty points are quiet moves; the first piece it meets becomes the screen, and the first piece after the screen is its only possible capture.

Legality: simulate, then look at the generals

generateLegalMoves plays every pseudo-legal move on a cloned board and rejects it if inCheck is then true. inCheck covers both real attacks (any enemy pseudo-move landing on the general) and the flying-general rule (both generals on one file with nothing between them) — so that unusual rule costs one loop, not special cases everywhere.

Repetition: position keys + a "gave check" flag per move

After each move, the board and side-to-move are stored as a string key, and whether the move gave check is recorded. When a key appears for the third time, the moves in that cycle are checked: if one side checked on every one of its moves, it loses for perpetual check; otherwise it's a draw.

The computer: Fairy-Stockfish over UCI

Fairy-Stockfish is the open-source (GPLv3) Stockfish derivative for chess variants, and one of the strongest Xiangqi engines there is. Its WebAssembly build (fairy-stockfish.wasm, ~1.6 MB) is vendored in xiangqi/vendor/fairy-stockfish/ and downloaded only when you first choose the computer. The page sends it plain-text UCI — setoption name UCI_Variant value xiangqi, then position startpos moves h3e3 h10g8 … and go depth N — and gets back a line like bestmove b1c3. Points use files a–i and ranks 1–10 from Red's side. The reply is matched against this page's own legal-move list before it's played, so the engine can only make moves the rules here allow.

That WASM build is multi-threaded, so it needs SharedArrayBuffer, which browsers only enable on cross-origin isolated pages (served with COOP/COEP headers). GitHub Pages can't set headers, so the page includes coi-serviceworker (MIT): a tiny service worker that adds those headers to every response for this folder. It installs on the first visit and reloads the page once. Strength levels set the engine's Skill Level and cap its search depth.

Board = SVG lines under a CSS grid of points

The 9×10 grid of clickable points is a CSS grid; the lines, palaces, river and position marks are one SVG drawn underneath, with each line passing through the centre of a grid cell. The drawing is symmetric under a half-turn, so flipping the board only changes which logical point each grid cell maps to — every other function thinks in logical coordinates only.
