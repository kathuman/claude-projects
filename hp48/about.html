An HP 48GX, emulated from its CPU up

This emulator rebuilds the 48GX's hardware in JavaScript: the Saturn CPU, the memory controller, the timers, the display and the keyboard. It then runs the calculator's own firmware. The CPU is written from the Saturn documentation, not copied from another emulator. It is checked against a separate disassembler and against the real ROM.

You bring the ROM

The ROM is HP's copyrighted firmware, so it is not included and never will be. On the calculator page you load a ROM file you own: dumped from your own calculator or obtained at your own discretion. It is kept in your browser, so it is there next time, and is never uploaded. Forget ROM deletes it. The emulator targets the 48GX, revision R.

The calculator between visits

Everything the calculator holds (its memory, its registers, its timers) is saved in your browser every few seconds and when you leave. Next time it carries on from exactly where it was. Its timers count the time you were away, as a real one does while switched off, so its clock stays right. You can also save the calculator to a file and open it again later or on another computer. The file holds the calculator's memory, never the ROM.

How programs are typed

Paste a program and the calculator types it on its own keyboard, so its own command line reads it, exactly as if you had typed it by hand. Each character's keys were found by the real ROM itself: every key was pressed, plain and shifted, and the result compared with what the ROM's CHR command gives for each character code. Brackets and quotes are typed as a person types them: the pair key, then stepping over its partner. The typist also waits for the calculator to be ready before each key, because a key pressed while it is still busy is not always read the same way. A few characters have no key on the 48GX (such as & and ;); you are told which were left out. Binary objects (files starting HPHP48-) need the serial port, which isn't emulated yet.

How it is checked

About 350 automated checks cover every instruction family and the memory controller's configuration protocol. They also cover the timers, the keyboard lines, the display registers, the key map, saving and restoring, the typist, the stack reader and the supply chain programs. A fuzz test decodes 20,000 random instructions with both the CPU and the disassembler. Tests on the real ROM run locally: they compare screens by hash, type pairs of key sequences that must leave the same screen, check every typed character against CHR, and check that a restored calculator carries on exactly as the original. The real firmware exposed two mistakes the unit tests had shared, and both are fixed. Details are in the README.
